# MFE People Hub

Выполненное тестовое задание по микрофронтендам: host-оболочка и два независимых микрофронтенда на Module Federation 2.0.

## Задание

Разработать небольшое приложение из host-оболочки и двух микрофронтендов.

- В первом отображается и редактируется профиль пользователя.
- Во втором показывается карточка этого же пользователя.
- После сохранения изменений карточка должна обновиться без перезагрузки страницы.
- Микрофронтенды не должны напрямую зависеть друг от друга.
- Добавить состояния загрузки и ошибки.

Дополнительно оцениваются: типизированный контракт между микрофронтендами, очистка подписок и поведение приложения, если один из модулей не загрузился.

## Стек

React 19, TypeScript 6 в strict, webpack 5 с `@module-federation/enhanced`, react-router 8, Tailwind CSS 4 с компонентами в стиле shadcn/ui, Mock Service Worker вместо бэкенда, pnpm workspaces, ESLint 10 с type-aware правилами.

Требуется Node 22.22+ (нижняя граница react-router 8). Проверялось на Node 24.21 и pnpm 12.6.

## Запуск

```bash
pnpm install
pnpm dev            # три dev-сервера; открывать http://localhost:3000
```

| Приложение    | Порт | Примечание                         |
| ------------- | ---- | ---------------------------------- |
| `host`        | 3000 | оболочка, точка входа для проверки |
| `mfe-profile` | 3001 | отдаёт и standalone-страницу       |
| `mfe-summary` | 3002 | отдаёт и standalone-страницу       |

```bash
pnpm dev:host / dev:profile / dev:summary   # по одному приложению
pnpm build          # production-сборка всех трёх
pnpm typecheck      # tsc --noEmit по пакетам
pnpm lint           # ESLint
```

Две оговорки. Типы ремоутов генерирует Module Federation в `apps/host/@mf-types`, поэтому `pnpm typecheck` в хосте проходит только после того, как ремоуты хотя бы раз поднялись или собрались. А `pnpm build` сознательно собирает без мок-бэкенда, поэтому смотреть приложение нужно через `pnpm dev`.

## Состав

```
apps/host/           маршруты, layout, шапка, RemoteBoundary
apps/mfe-profile/    форма профиля, вкладки как подмаршруты; exposes ./ProfileApp
apps/mfe-summary/    read-only карточка; exposes ./SummaryCard
packages/contracts/  User, AppEvents, шина, UserApi, правило заполненности
packages/api-client/ реализация UserApi поверх fetch, без состояния
packages/mock-api/   обработчики Mock Service Worker, только для разработки
packages/ui/         компоненты и токены темы
```

Общего у микрофронтендов — только `@people-hub/contracts`. Данные ходят по HTTP.

## Ключевые решения

**Типизированная шина на eventemitter3.** Модули общаются через одну шину: отправитель не знает получателей, поэтому `mfe-profile` сообщает о сохранении, не импортируя `mfe-summary`. Обёртки над библиотекой нет — `appBus` это `EventEmitter`, параметризованный картой событий из контракта, так что неизвестное имя события или неверная нагрузка не компилируются. `on` не возвращает функцию отписки, поэтому каждая подписка держит именованный обработчик и парует `on` с `off` в cleanup эффекта.

**`contracts` — singleton, слой данных — нет.** Шина хранит подписчиков в памяти модуля, поэтому вторая копия молча перестала бы пропускать события через границу микрофронтенда. Клиент API, наоборот, состояния не хранит — каждый бандл несёт свою копию, а единственный источник правды лежит за сетью. Разделяемого изменяемого состояния между микрофронтендами нет.

**Вложенный роутинг с общим роутером.** Хост владеет префиксом и отдаёт его целиком (`/profile/*`), модуль описывает своё поддерево относительными путями и не знает, куда его смонтировали. 404 внутри префикса — забота модуля. `react-router` объявлен singleton: два экземпляра истории на странице скрыли бы навигацию модуля от хоста.

**Каждый потребитель грузит данные сам и защищается от устаревшего ответа.** При монтировании вызывается `getUser()`, потом подписка — поздний подписчик не остаётся с пустым экраном. Это лекарство создаёт гонку: ответ на запрос, отправленный до сохранения, может затереть свежие данные. Каждый потребитель нумерует запросы и отбрасывает неактуальные.

**`shareStrategy: 'loaded-first'` вместо умолчания.** При дефолтном `version-first` рантайм перед разрешением любой общей зависимости инициализирует шаринг по всем объявленным ремоутам, поэтому один недоступный ремоут гасит страницу целиком ещё до первого рендера — `RemoteBoundary` не успевает сработать. Умолчание решает расхождение версий между независимо собранными бандлами; в этом репозитории его нет по построению.

**Ремоуты грузятся через рантайм-API.** `RemoteBoundary` — это ErrorBoundary плюс Suspense с кнопкой повтора. Честный повтор требует и `registerRemotes(..., { force: true })`, и нового `lazy()`: рантайм федерации кеширует неудачу, а `React.lazy` — отклонённый промис. Скомпилированный `import('summary/SummaryCard')` продолжает указывать на захваченный ранее контейнер, поэтому используется `loadRemote`, а типовая связь сохранена через `typeof import(...)`.

**Tailwind между бандлами.** Preflight отгружается один раз, хостом; ремоуты добавляют его только в standalone-входе. Токены темы лежат в одном файле и импортируются всеми тремя приложениями — иначе одноимённые утилиты получили бы разные значения, и побеждал бы бандл, загрузившийся последним. Каждое приложение сканирует и свои исходники, и общий пакет.

**Монорепо не противоречит независимости деплоя** — её обеспечивает Module Federation, а не число репозиториев. Общие пакеты отдают TypeScript-исходники и не имеют шага сборки; Nx и Turborepo на трёх приложениях не окупают своей конфигурации.

## Что посмотреть

Откройте «Профиль», измените имя и заполните должность, нажмите «Сохранить»: карточка обновится без перезагрузки, индикатор заполненности дойдёт с 67% до 100%, инициалы в шапке тоже поменяются — три независимых подписчика на одно событие.

Переключите вкладки: адрес меняется на `/profile/contacts` и обратно, оба открываются по прямой ссылке. Полей на второй вкладке нет — модель содержит только то, что показывает карточка, а вкладка оставлена, чтобы был виден вложенный роутинг.

Включите в шапке «Сымитировать ошибку API» и перейдите между страницами: оба модуля покажут собственное состояние ошибки и рабочую кнопку повтора.

Запустите приложения по отдельности и остановите то, что на порту 3002: страница продолжит работать, на месте карточки появится плашка с повтором, сохранение пройдёт. Поднимите модуль обратно и нажмите «Повторить» — карточка вернётся без перезагрузки.

## Ограничения

Тестов и CI нет — сознательный пропуск. Адреса ремоутов зашиты в код, а не читаются из конфигурации окружения; сделать их динамическими — очевидный следующий шаг. Мок хранит состояние в памяти страницы, поэтому перезагрузка возвращает данные к исходным.
