# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Обзор

host-оболочка и два независимых микрофронтенда на Module Federation 2.0 (`@module-federation/enhanced` + webpack 5), React 19, TypeScript 6 в strict, pnpm workspaces. `mfe-profile` редактирует User, `mfe-summary` показывает его карточку; прямых зависимостей между ними нет. Единственное общее — пакет `@people-hub/contracts`: типы домена, карта событий, шина, `UserApi` и правило подсчёта completeness.

Обоснования ключевых решений уже написаны и их не нужно выводить заново: раздел «Ключевые решения» в `README.md` (английский) и `README.ru.md` (русский). Оба файла держать синхронными по смыслу.

Язык: идентификаторы и комментарии в коде — английские, UI-строки — русские. Документация в двух версиях: `README.md` на английском, `README.ru.md` на русском.

## Команды

```bash
pnpm install
pnpm dev            # три dev-сервера параллельно; проверять на http://localhost:3000
pnpm dev:host       # host        3000
pnpm dev:profile    # mfe-profile 3001, тот же порт отдаёт standalone-режим
pnpm dev:summary    # mfe-summary 3002, тот же порт отдаёт standalone-режим

pnpm build          # production-сборка всех трёх приложений
pnpm typecheck      # tsc --noEmit по всем пакетам
pnpm lint           # ESLint 10 с type-aware правилами
pnpm format         # Prettier; format:check — только проверка
```

Одно приложение: `pnpm --filter @people-hub/host run <script>` (также `@people-hub/mfe-profile`, `@people-hub/mfe-summary`).

Тестов и тест-раннера в репозитории нет — это осознанный пропуск, зафиксированный в README (раздел «Ограничения»), а не незаконченная работа.

`pnpm typecheck` в host проходит только после того, как ремоуты хотя бы раз поднимались (`pnpm dev` или `pnpm build`): типы `profile/ProfileApp` и `summary/SummaryCard` генерирует Module Federation в `apps/host/@mf-types`, куда `paths` хоста и указывает. Каталог не коммитится.

Общие пакеты отдают TypeScript-исходники и не имеют шага сборки — их компилирует webpack приложения-потребителя. Правки в `packages/*` подхватываются dev-серверами сразу, `dist` у пакетов нет, watch-цепочек нет.

## Карта репозитория

```
apps/host/          маршруты, layout, шапка, RemoteBoundary, загрузка ремоутов
apps/mfe-profile/   форма профиля, вкладки как подмаршруты; exposes ./ProfileApp
apps/mfe-summary/   read-only карточка; exposes ./SummaryCard
packages/contracts/ User/UserPatch, AppEvents, appBus, UserApi, profileCompleteness
packages/api-client/ реализация UserApi поверх fetch, без состояния
packages/mock-api/  обработчики Mock Service Worker: бэкенд для разработки
packages/ui/        компоненты shadcn/ui и theme.css с дизайн-токенами
build/federation-shared.cjs   раздел shared, общий для всех трёх webpack-конфигов
```

## Как связаны модули

Поток один и тот же для всех трёх сторон: при монтировании потребитель сам читает `userApi.getUser()`, потом подписывается на `appBus`. Событие — уведомление об изменении, а не источник данных, поэтому поздний подписчик не остаётся с пустым экраном.

- `mfe-profile` — единственный писатель. После успешного `saveUser(patch)` публикует `user:updated` с целым свежим `User`. На своё же событие не подписывается: это дралось бы с черновиком формы.
- `mfe-summary` и `useHostUser` в хосте — читатели: `getUser()` при монтировании плюс подписка.
- `mfe-profile` публикует `navigation:changed`, хост рисует по нему заголовок и крошки, не зная внутренних маршрутов модуля.

Экспонируемые компоненты не принимают props вообще: шина, доступ к данным и дизайн-система приходят через shared-контракт, а не через точку монтирования.

Добавление события начинается с правки `AppEvents` в `packages/contracts/src/events.ts` — карта событий типизирует `emit`/`on`, поэтому неизвестное имя или неверная нагрузка становятся ошибкой компиляции. Добавление поля профиля начинается с `EDITABLE_USER_FIELDS` в `packages/contracts/src/user.ts`: этот массив управляет и `UserPatch`, и построением патча, и процентом заполненности.

## Инварианты, которые легко сломать молча

Общая черта почти всех пунктов ниже: нарушение не роняет сборку, а проявляется в рантайме — вторым React, потерянным событием или сброшенными стилями.

### Федерация

- Раздел `shared` живёт только в `build/federation-shared.cjs` и подключается всеми тремя конфигами. Три разошедшиеся копии дают второй экземпляр React или шины, а не ошибку сборки.
- Singleton-ами объявлены те пакеты, у которых важна идентичность: `react`, `react-dom`, `react/jsx-runtime` (отдельный запрос, `react` его не покрывает), `react-router` и два workspace-пакета — `contracts` и `ui`. Для последних `requiredVersion: false` — `workspace:*` не semver-диапазон. `api-client` в `shared` не входит сознательно: он без состояния, и копия в каждом бандле безвредна.
- `shareStrategy: 'loaded-first'` обязателен во всех трёх конфигах. Дефолтный `version-first` тянет remote entry всех ремоутов перед разрешением любой общей зависимости, поэтому один недоступный ремоут гасит всю страницу ещё до первого рендера — `RemoteBoundary` не успевает сработать.
- `webpack-dev-server` не перечитывает `webpack.config.js`: любую проверку конфигурации федерации делать только с полным перезапуском процесса, иначе получите ложный результат.
- Точка входа каждого приложения — только `void import('./bootstrap')`. Синхронная инициализация React в `index.ts` ломает сборку ошибкой про eager consumption.
- `output.publicPath: 'auto'` нужен рантайму, но тегам скриптов задан абсолютный `publicPath: '/'` в HtmlWebpackPlugin — иначе прямая ссылка `/profile/contacts` заставит браузер искать `main.js` внутри `/profile/`.
- Генератор типов компилирует только экспонируемые файлы, поэтому `src/globals.d.ts` (декларация `*.css`) передаётся ему явно через `dts.generateTypes.additionalFilesToCompile`.
- Dev-серверы ремоутов отдают `Access-Control-Allow-Origin: *`: манифест хост забирает через `fetch`.
- Правило swc-loader в каждом приложении обязано включать `packages/` в `include` — общие пакеты приезжают исходниками.

### Загрузка ремоутов и восстановление

- Ремоуты грузятся через рантайм-API (`loadRemoteComponent` поверх `loadRemote`), а не скомпилированным `import('summary/SummaryCard')`: после перерегистрации скомпилированный импорт продолжает указывать на захваченный ранее контейнер. Типовая связь сохранена через `type ... = typeof import('...')`.
- Честный повтор в `RemoteBoundary` требует обоих шагов сразу: `registerRemotes([...], { force: true })` (рантайм кеширует неудачу) и новый `lazy(loader)` (React.lazy навсегда запоминает отклонённый промис). Alias при перерегистрации обязан совпадать с именем, под которым ремоут зарегистрировала сборка.
- Адреса ремоутов описаны один раз в `apps/host/src/remotes.json` и читаются и webpack-конфигом, и кнопкой повтора.
- `loader` передаётся в `RemoteBoundary` из модульной константы: новая функция на каждом рендере создавала бы новый ленивый компонент.

### Роутинг

- Хост отдаёт ремоуту префикс целиком (`/profile/*`) и не знает, что внутри. 404 внутри префикса обрабатывает ремоут.
- Внутри ремоута запрещены абсолютные пути и ведущие слэши в `Route`/`Link`. Свой префикс модуль узнаёт во время выполнения через `useMountPath()`, а не из константы: в splat-маршруте относительная ссылка разрешается от полного текущего пути, поэтому `<Link to="contacts">` со страницы `/profile/contacts` вёл бы на `/profile/contacts/contacts`.
- Объекты `NavigationState` для `useNavigationState` объявляются на уровне модуля. Новый объект на каждом рендере публиковал бы `navigation:changed` на каждое нажатие клавиши.

### Данные, события, гонки

- `appBus` — экземпляр `EventEmitter` из eventemitter3, параметризованный картой `AppEvents` (библиотека принимает аргументы слушателя кортежем, адаптер `BusEvents` лежит в `bus.ts`). Обязан существовать на странице в единственном экземпляре, иначе `user:updated` не пересечёт границу модуля — без ошибки в консоли. Помимо singleton в `shared` создание шины защищено проверкой на `globalThis`, которая громко предупреждает о второй копии.
- `on` в eventemitter3 не возвращает функцию отписки: каждая подписка обязана держать именованный обработчик и вызывать `off` с той же ссылкой в cleanup. Инлайновая стрелка в `on` означает подписку, которую невозможно снять.
- Каждый потребитель нумерует поколения: запрос запоминает свой номер, обработчик события увеличивает счётчик, ответ применяется только если номер ещё актуален. Без этого ответ на запрос, отправленный до сохранения, затрёт свежие данные. Логика продублирована в `useHostUser`, `useUserSnapshot` и `useProfileEditor` осознанно — общий код между независимо деплоящимися модулями был бы связанностью.
- Обработчик мока читает состояние **до** задержки, а не после: так ведёт себя сервер, успевший ответить до того, как запись легла, и прятать эту гонку нельзя.
- `user:updated` публикуется только после подтверждения от API и несёт целого `User`, а не патч.
- Данные ходят по HTTP, а не через общий модуль: разделяемого изменяемого состояния между микрофронтендами нет. `singleton` у `@people-hub/contracts` — настоящее архитектурное требование, потому что шина хранит подписчиков в памяти модуля.
- Мок подключается динамическим импортом под проверкой `NODE_ENV` и в production-бандл не попадает. Регистрирует воркер тот, кто владеет страницей: host и каждый standalone-вход на своём origin; сами микрофронтенды про мок не знают.
- Замена мока на настоящий бэкенд не трогает ни один модуль: потребители знают только интерфейс `UserApi` из контракта.

### Стили

- Preflight отгружает только host (`@import 'tailwindcss'` целиком). Ремоуты подключают лишь theme и utilities, а preflight добавляют отдельным `standalone.css`, который подключается только из `bootstrap.tsx`. Второй preflight на странице сбросит уже отрисованные стили оболочки.
- Токены темы живут только в `packages/ui/src/theme.css` и импортируются всеми тремя приложениями. Разошедшиеся темы дают одноимённым утилитам разные значения, и побеждает бандл, загрузившийся последним.
- Каждое приложение сканирует и себя, и общий пакет: `@source '../src'` плюс `@source '../../../packages/ui/src'`. Иначе классы из `packages/ui` не попадут в CSS бандла.
- Компоненты shadcn/ui добавляются только в `packages/ui` (`components.json` настроен на этот путь) и реэкспортируются из `src/index.ts`. Пакет singleton: примитивы Radix живут на контекстах и порталах, две копии дают разорванные контексты.

## Стиль кода

- Prettier: одинарные кавычки, точки с запятой, `printWidth: 100`, trailing commas везде.
- `verbatimModuleSyntax` включён — импорты типов пишутся через `import type`. Также включены `noUnusedLocals` и `noUnusedParameters`.
- ESLint: `recommendedTypeChecked` для `apps/*/src` и `packages/*/src` плюс правила хуков — подписки в этом проекте живут и умирают по функциям очистки, которые эти правила и проверяют.
- Комментарии объясняют, почему сделано именно так, и особенно — какой отказ предотвращает конструкция. Плотность в существующих файлах невысокая; держать её такой же.
- Решения, которые дороже всего пересматривать, дописываются абзацем в раздел «Ключевые решения» обоих README.
